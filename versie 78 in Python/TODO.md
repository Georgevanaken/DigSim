# DigSim Python port: to do

Close translation of DigSim v78 (Free Pascal, G. van Aken, AGPL-3.0) to Python.
Status: all units translated and validated against a Free Pascal build at the same step rate (see "Validation findings"). 24 fast tests pass, plus 2 slow regression tests (`DIGSIM_SLOW=1`; all 26 pass, about 6 min). The code has been refactored (enums, dataclass groups, English names, type hints, vectorised hot spots) with outputs kept byte-identical to the validated port.

## Validation findings (Pascal built with FPC 3.2.2 in a temporary folder)

- The reference `Results.txt` in the v78 folder is NOT reproduced by Pascal at 20 or 60 steps/min (60-100 of 166 columns differ), so it cannot serve as the baseline. Use own Pascal runs instead.
- Pascal build hint: remove `crt`/`clrscr` (digsim_v78.pas, insulin.pas) in a temp copy; with redirected stdout they hang the program.
- Fixed in the port: missing `colon()` call in `make_step`; `np.seterr(under='ignore')`; integer step counting for the time loops; first meal is loaded with `>=` (Pascal's float time is 7.9e-11 > 0 at the start of the main loop, so the meal at t=0 starts at the first step).
- Init phase (500 min fasted) agrees with Pascal at the same step rate: step 1 exactly, later steps to ~1e-6 and 0.1% by step 10000. The residual is the discontinuous pH bisection (Tol 0.001) plus x87 vs double arithmetic; it is not a translation bug.
- After the meal fix the first minutes agree to ~1% (mouth exactly).
- Full 3500-minute run at 20 steps/min vs Pascal at 20 steps/min: median relative difference ~0 in all 166 columns; serum glucose and gastric volume within ~0.5%; outliers are only pulse-like columns (salivary amylase when the mouth is empty, emptying stresses, solids) from small timing shifts. Late in the run (t>2500) <1% of columns differ by more than 1%.
- meal.txt uses compound number 78 (> 50): Pascal reads 0 for pH/viscosity out of array bounds; the port reproduces this.
- Remaining: steps 2-4 below if desired.
- Regression baselines (item 5) are done: `tests/baselines/` holds Pascal output at 20 steps/min (first 40 rows, and every 50th row of the full run); `tests/test_regression.py` compares 29 key columns within 5-6% of their range. The slow tests need `DIGSIM_SLOW=1` (first test about 2 min after the speed-ups below; the full run took about 26 min wall-clock on this machine and its sampled comparison passed against the Pascal baseline). Speed-ups: `gut_hormones`, `absorption_in_small_intestine`, `mucus_layer` and the `make_step` transport loops are vectorised (profiled step cost roughly halved); the original scalar versions are kept in `tests/ref_main_part3.py` and `tests/ref_transport.py` and checked in `tests/test_vectorised_equivalence.py`. `tools/build_pascal_reference.ps1` regenerates the Pascal reference reproducibly (the output was byte-identical on rebuild).
